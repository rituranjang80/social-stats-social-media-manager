# Cursor Prompt — Generate Complete Current Application URL Inventory

## OBJECTIVE

Analyze the **entire existing application** and generate a complete, accurate inventory of **ALL URLs/routes currently available in the application**.

Do NOT modify, delete, refactor, rename, or break any existing code.

This is an **analysis and documentation task only**.

---

## 1. SCAN THE ENTIRE PROJECT

First inspect the complete project structure.

Identify all relevant:

* React routes
* React Router routes
* Django URLs
* Django REST Framework routes
* API endpoints
* ViewSets
* routers
* nested routers
* authentication URLs
* admin URLs
* management URLs
* analytics URLs
* social-media URLs
* workspace URLs
* team URLs
* client URLs
* settings URLs
* media URLs
* composer URLs
* calendar URLs
* video URLs
* reporting URLs
* webhook URLs
* OAuth callback URLs
* health-check URLs
* utility endpoints

Do NOT rely only on manually known URLs.

Search the source code.

---

# 2. FRONTEND URLS

Inspect all frontend routing files and identify every route.

Search for patterns such as:

```text
<Route
createBrowserRouter
createHashRouter
useRoutes
path:
react-router
RouterProvider
```

For every frontend route identify:

* URL/path
* Component/page
* Parent route
* Child route
* Layout
* Authentication requirement
* Permission/RBAC requirement
* Workspace requirement
* Status

Example:

| Type     | URL                          | Component | Auth | RBAC                 |
| -------- | ---------------------------- | --------- | ---- | -------------------- |
| Frontend | `/admin/analytics/analytics` | Analytics | Yes  | Analytics permission |
| Frontend | `/admin/analytics/calendar`  | Calendar  | Yes  | Analytics permission |

Do not invent values.

Use the actual source code.

---

# 3. DJANGO URLS


```text
urls.py
```

Identify every backend URL.

# 4. DRF API ENDPOINTS

Identify every Django REST Framework endpoint.

For each endpoint provide:

* HTTP method
* URL
* View/ViewSet
* Serializer
* Authentication
* Permission
* Workspace scope
* Purpose

Example:

| Method | API URL    | View             | Permission | Purpose         |
| ------ | ---------- | ---------------- | ---------- | --------------- |
| GET    | `/api/...` | AnalyticsViewSet | ...        | Analytics data  |
| POST   | `/api/...` | SyncView         | ...        | Synchronization |

If a ViewSet automatically generates routes, inspect the router and list the generated routes.

# 8. URL PARAMETERS

For dynamic URLs, preserve their actual parameters.

For example:

```text
/admin/clients/:id
/admin/workspaces/:workspaceId
/admin/posts/:postId
```

Document:

```text
Parameter
Type
Purpose
```

If the application uses query parameters, document them separately.

Example:

```text
/admin/analytics/calendar?mode=list
```

Document:

```text
mode
Possible values: list, calendar, ...
```

Only include values that are actually supported by the code.

---

# 9. DUPLICATE / ALIAS ROUTES

Identify duplicate or alias URLs that point to the same page/component.

Example:

```text

/admin/analytics/analytics
```

If both exist, report both and identify whether they render:

* same component
* redirect
* different component

# 10. REDIRECTS

Identify all redirects.

For each redirect provide:

```text

```


Do not miss authentication redirects.

# 19. BROKEN / ORPHAN ROUTES

Also identify:

### Orphan frontend routes

Routes that exist in the router but appear to have no usable page/component.

### Orphan backend endpoints

Endpoints that appear registered but have no frontend usage.

### Missing frontend routes

If frontend code references a URL that is not registered, report it.

### Missing backend endpoints

If frontend API calls reference an endpoint that does not exist, report it.

### Broken links

Search for:

```text
href=
navigate(
<Link
window.location
fetch(
axios
apiClient
```

and identify URLs that appear invalid or unregistered.
